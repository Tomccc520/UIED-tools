# GIF 压缩与视频转 GIF 验证（2026-10-19）

基准：`9b4c11e0`，版本 `3.0.3`。本轮保留 Vue 3、现有工具路由及消费门禁，不新增依赖、第三方上传、版本升级、Git 提交或部署。

## GIF 压缩

入口：`/tools/gif-compress`。当前为单文件本地处理；注册表已去掉“支持批量压缩”的错误承诺。后台或历史缓存若保留旧简介，需通过正常配置发布流程另行更新，本轮未改数据库。

修复：

- 按 GIF 帧补丁与 disposal 规则还原画面，避免透明补丁覆盖已显示的像素。
- 合并重复帧或抽帧时保留正确时长，保留源循环次数；没有循环扩展时不强制无限循环，超长延迟拆分为合法值。
- 为整项任务设置 120 秒超时，覆盖依赖加载、解析和编码；线程异常、取消、卸载均清理任务与编码器资源。压缩期间锁定上传和参数，失败后清除旧结果并允许重试。
- 解码前限制画布宽×高×帧数不超过 3200 万，单文件不超过 50MB。
- 透明背景暂不支持安全重新编码：保留原文件，明确说明未应用自定义参数，按钮显示“下载原图”。编码后体积更大时同样明确保留原图，并显示实际输出尺寸和帧数。
- “画质优先”保留原尺寸和全帧，重新量化颜色仍可能有损，已移除无损暗示。
- 修正 320px 工具栏下载按钮裁切，操作按钮完整换行，画质说明占满卡片宽度。
- 删除重复且没有 provider 的 `useHead`，由现有全局 SEO 管理标题、描述和索引设置。

实际验证：

| 输入 / 操作 | 独立检查结果 |
| --- | --- |
| 192×128、4 帧、循环 2 次，默认压缩 | 导出 192×128、4 帧、延迟 100/250/400/150ms，总计 900ms，循环 2 次 |
| 同源高压缩预设 | 导出 163×109、2 帧、延迟 350/550ms，总计仍为 900ms，循环 2 次 |
| 带 disposal 1/2/3 的帧合成 | 辅助函数输出 RGBA 与 Pillow 合成画面逐像素一致 |
| 透明 GIF | 下载内容与源文件二进制一致；页面明确提示保留原图和不应用自定义参数 |
| 损坏 GIF | 显示“GIF 预览加载失败，文件可能损坏，请重新上传”，提供重新上传入口，无无限加载 |
| 320 / 375 / 768 / 1440px | 一个 H1，无横向溢出；重新上传、开始压缩及下载原图均在视口范围内 |

测试 GIF 含人工添加的注释块，用于确保进入编码路径。输出大小不作为常见 GIF 压缩率或优于原编码器的证据。

当前边界：GIF 帧解码和合成仍在主线程分段执行，编码使用 Worker；尚未完成 Safari / Firefox 实测。透明背景重新编码、批量 GIF 不是本轮已实现能力。

## 视频转 GIF

入口原已存在：`/tools/video/gif`。GIF 压缩页已增加直达入口。

修复：

- 等待每次 seek 和逐帧捕获，捕获异常进入统一失败反馈，不再遗留未完成任务。
- 生成前即锁定任务，快照源文件和参数；调整参数不会错误修改上一次结果信息。
- 设置 120 秒任务超时、5 秒 seek 超时，支持取消，离开页面终止编码器和线程。
- 按累计时间量化 GIF 的 10ms 帧延迟，并裁切末帧，避免 30fps、倍速和不足一帧片段出现总时长漂移或零延迟变成 500ms。
- 修复本页 Element Plus 数字输入框动态 ARIA 状态过期，保留输入 DOM、焦点与真实禁用状态；三个数字框有明确中文名称。
- 视频页使用一个 H1；共享标题组件默认仍为 H2，其他页面保持原行为。

当前限制：200MB、截取最长 30 秒、最多 450 帧、累计输出像素不超过 8000 万。宽度 80–960px、帧率 1–30fps、速度 0.5/1/1.5/2 倍；实际可读取格式取决于浏览器解码支持，优先 MP4 / WebM，没有 FFmpeg 解码兜底。

实际下载并用 Pillow 独立解码：

| 参数 | 产物 |
| --- | --- |
| H.264 MP4，320×180、2 秒，10fps、1 倍 | 320×180、20 帧、总时长 2000ms |
| 同源 30fps、2 倍 | 320×180、60 帧、总时长 1000ms |
| 截取 0.15 秒、160px、10fps、2 倍 | 160×90、2 帧、50/30ms，总时长 80ms，符合 10ms 精度 |

结果页在 320 / 375 / 768 / 1440px 均无横向溢出且只有一个 H1。
