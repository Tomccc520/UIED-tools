# UIEDTool 后台运营配置规范 V1（官网设置）

## 1. 目标与范围

本规范用于统一 `likeadmin-go/admin` 的「官网设置」后台体验，核心目标：

- 运营同学可直接配置，不需要理解开发实现细节。
- 同类页面结构一致，减少“每页一套交互”的混乱感。
- 前端消费字段稳定，避免频繁改字段名和 JSON 结构。

适用页面：

- `http://127.0.0.1:5180/official_site/*`
- 当前重点：`/official_site/frontend_layout`、`/official_site/hot_tools`、`/setting/website/information`

参考的市面后台范式（用于对齐，不做照搬）：

- Ant Design Pro：统一页面骨架 + 标准化表单/列表行为
- Arco Design Pro：配置页分组清晰、反馈明确
- 语雀/飞书后台：面向运营语言，不暴露开发结构

---

## 2. 信息架构规范（必须）

「官网设置」统一一级菜单，不再散落到系统设置。

二级菜单固定为：

- `站点基础信息`
- `前端布局配置`
- `热门工具配置`
- `图标库管理`
- `页面运营配置`

说明：

- 「页面运营配置」承接更新记录页、AI 工具页等页面级入口文案。
- `前端布局配置` 只处理结构与导航，不承载页面级文案。

---

## 3. 页面骨架规范（必须）

每个官网设置页面统一 6 个区块，从上到下顺序固定：

1. `PageHeader`：标题 + 一句说明 + 状态标签（草稿/已发布）
2. `QuickActions`：预览、体检、导入、导出、恢复默认
3. `Metrics`：只展示 4~8 个核心指标（数量、状态）
4. `ConfigBody`：按业务分组卡片，字段集中编辑
5. `ValidationPanel`：保存前问题清单（可定位到字段）
6. `FooterActions`：取消、保存草稿、发布生效（主按钮唯一）

禁止项：

- 不允许在同页混放“结构配置 + 页面文案 + 系统备案”三类职责。
- 不允许“上方一套按钮 + 卡片里再一套重复按钮”。
- 不允许只显示 JSON 字符串给运营直接编辑（可读写分离）。

---

## 4. 交互规范（必须）

### 4.1 保存流程

- 页面支持 `保存草稿` 与 `发布生效` 两阶段。
- 离开页面前有未保存变更时，统一弹出确认。
- 保存后固定反馈：成功提示 + 最近保存时间 + 错误定位入口。

### 4.2 表单行为

- 同类字段标签宽度统一（建议 `120`）。
- 链接字段实时校验：仅允许 `/`、`#`、`http(s)`。
- 列表项支持：新增、删除、上移、下移、批量清理空项。

### 4.3 状态反馈

- 统一 4 态：加载中、空状态、校验失败、保存成功。
- 错误文案必须可执行，例如：
  - `链接格式错误：仅支持 /、#、http(s)`
  - `分类菜单缺少映射：请在“工具分类树”补全`

---

## 5. 字段模型规范（必须）

运营配置字段统一命名为 `tools*` 前缀，按域分组：

- `toolsLayout*`：结构布局（侧栏、头部、页脚）
- `toolsPageOps*`：页面运营（文案、顶部入口）
- `toolsCatalog*`：工具分类与工具列表

数组型字段统一结构：

```json
[{ "name": "显示名", "link": "/path-or-https-or-#anchor" }]
```

禁用混杂结构：

- 不允许同一字段同时出现 `name/title/text` 三套命名。
- 不允许同类字段部分用 JSON 字符串、部分用对象数组。

---

## 6. 视觉规范（必须）

只使用全局样式变量与通用类，禁止页面私有魔法数堆砌。

统一值建议：

- 页面区块间距：`24px`
- 卡片内部垂直间距：`16px`
- 行内控件间距：`8~12px`
- 圆角：`8px`
- 主按钮：同层唯一 `primary`

说明：

- 配置后台优先“清晰、稳定”，不过度装饰，不引入多余阴影和炫技动画。

---

## 7. 验收清单（上线前必须）

- 菜单层级清晰，运营能在 3 次点击内到达目标配置项。
- 任意配置项从「后台保存」到「前端生效」链路可回归。
- 页面支持导入导出，且导入后自动体检。
- 有明确回退策略：恢复默认 / 最近一次发布版本。
- 无开发术语暴露给运营（例如“JSON字段名”“接口参数名”）。

---

## 8. 前端布局页（frontend_layout）改造要求

当前页问题判定：

- 职责偏多，布局结构与页面运营配置混在一起。
- 快捷按钮数量过多，信息层级不够清晰。
- 虽然功能全，但运营路径不短，认知成本高。

V1 改造顺序：

1. 先拆职责：`前端布局配置` 与 `页面运营配置` 分页分离。
2. 再统一骨架：按“6 区块模板”重排。
3. 最后做体验：补字段说明、错误定位、一键体检结果面板。

---

## 9. 执行策略（本项目）

按两周节奏分批落地：

- 第一批：`frontend_layout`、`hot_tools` 完全套用本规范。
- 第二批：`information` 与其他官网设置页统一骨架和交互。
- 第三批：沉淀通用组件（Header/QuickActions/ValidationPanel）。

发布规则：

- 每批必须包含：规范对齐说明 + 回归结果 + 变更截图。
