# UIED-Tools 3.0.3 API 审计与整改清单

## 1. 当前结论

文案类接口已完成同域化，但全站 API 尚未全部完成后台收口。2026-08-30 实测仍有 8 个工具由浏览器直接请求第三方，其中 6 个上游已失效或明显不稳定，另外 2 个当前可用但仍存在生产跨域、限流和供应商切换风险。

Vite `server.proxy` 只解决本地开发请求，不等同于生产后台 API。生产页面不得把 Vite 开发代理当作正式接口层。

## 4. 正式接口架构

新接口统一采用以下链路：

`Vue/React 页面 → src/services → /api/common/* → Go Provider Adapter → 白名单上游`

后台必须提供：

- 固定域名白名单，禁止用户提交任意上游地址，避免 SSRF。
- 连接与整体超时、响应体大小限制、内容类型校验和明确错误码。
- 对低频变更数据设置缓存；对连续失败上游做短时熔断，避免拖慢页面。
- 图片上传使用 `POST multipart/form-data`，图片输出统一走受控代理或对象存储。
- 管理后台保存供应商启停、地址、密钥和超时时间；前端不感知供应商字段。
- 记录上游成功率、P95 延迟、降级次数和最后成功时间，便于运营巡检。

## 5. 发布前门禁

- 全站源码扫描不得出现业务组件直接请求第三方 HTTP API；静态资源域名另行维护白名单。
- 每个后台契约至少覆盖成功、上游错误、超时、格式异常和参数非法测试。
- 浏览器验证加载、空、成功、失败、重试和移动端布局，不只验证接口返回 200。
- 版本号需一次性同步到前端包、锁文件、Go 配置、发布脚本和更新日志。当前项目元数据仍为 `3.0.1`，与“3.0.3 开发阶段”口径不一致，发布前必须原子更新。
