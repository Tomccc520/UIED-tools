# 压缩工具排查与修复（2026-10-29）

本轮基于 3.0.6 工作区，检查图片、GIF 与 PDF 压缩，延续已完成的视频压缩优化。这里只记录本轮证据，不表示全部文件、设备及浏览器均已通过。没有升级版本、生成部署包或更新生产环境。

## 修复内容

### 图片压缩

- 修改质量、尺寸或 PNG 参数后立即撤下旧结果，避免单张和 ZIP 下载使用未应用新参数的文件。
- 支持停止当前批次；保留已完成图片，未处理图片保持待处理，取消后不再自动下载不完整 ZIP。下一批使用独立取消信号。
- JPG/WebP 压缩前识别动态 WebP，明确拒绝，避免静默丢失动画帧；头部读取也受取消和超时约束。
- ZIP 改为 STORE 打包，不再重复压缩已经编码的图片；仍保留输出重名防覆盖。
- 独立的设计图片压缩页补充 APNG/动态 WebP 保护、PNG 质量参数无效说明、体积增加提示及同格式原尺寸保留原图逻辑，并提供批量工具入口。
- 独立设计页使用实际 MIME 的 Blob URL 下载，延迟释放地址，修复当前内嵌浏览器下直接下载 data URL 没有产物的兼容问题；这不表示所有浏览器都不支持 data URL 下载。

### GIF 压缩

- 使用与已安装 gif.js 版本匹配的 Worker，修复旧 Worker 忽略抖动和全局色板参数的问题。
- 8–128 色使用固定色板，消除先减色再训练色板的重复处理，编码结果不超过目标颜色数；256 色继续自适应分析。
- 固定色板模式禁用不生效的颜色分析精度设置，并说明原因。均衡预设默认关闭抖动，用户仍可主动开启。
- “重新上传”直接打开选择器，取消选择不清除已有结果。

### PDF 压缩

- 默认使用 qpdf 优化对象及压缩流，保留普通文档的文字、链接、表单和页面尺寸；结果变大时保留原文件。
- 原来的页面栅格化改为明确选择的“扫描件压缩（有损）”，持续展示文字、链接及表单的损失说明；移除没有作用的元数据开关和未经验证的算法宣传。
- qpdf 在独立 Worker 执行，每个文件有 5 分钟超时，支持主动取消并释放线程；扫描件模式取消当前解析或绘制。
- 参数变化撤下旧产物；处理中只标记当前文件，结构压缩使用无法估时的进度反馈。打包时锁定配置和列表操作，卸载后不再触发迟到下载。
- 工具注册描述和已知旧 SEO 文案同步更新，避免继续宣传默认会破坏文字结构的处理方式。

## 真实产物验证

全部样本为本地生成的测试文件，没有使用用户文件，也没有播放音频。浏览器操作针对本轮生产构建的本地预览服务；下载后使用独立读取器检查。

| 工具 | 样本与结果 | 检查内容 |
| --- | --- | --- |
| 图片压缩 | 两张同名透明 PNG 与一张 JPG，ZIP 含 3 个独立文件 | PNG 160×100，逐像素 RGBA 与输入一致；同名输出带序号；JPG 3,554,931 → 737,434 字节，1600×1000，实际 JPEG 文件头与后缀一致 |
| 设计图片压缩页 | 真实 PNG 下载 258 字节 | 内嵌浏览器下载事件和磁盘文件均产生，独立解码及文件头确认是带透明通道的 PNG |
| GIF 压缩 | 不透明 GIF 72,663 → 32,786 字节 | 12 帧、160×90、总时长 1500ms、循环次数 3 保留，帧序正确，128 色设置下每帧不超过 128 色 |

另外实际验证了图片停止批次保留已完成结果、动态 WebP/APNG 错误提示及恢复上传、PDF 切换模式清除旧下载。PDF 小样本处理过快，浏览器没有可靠命中取消窗口，取消、超时和迟到回调由自动化用例验证。

图片、GIF、PDF 主页面分别在 320/375/768/1440px 检查，单个 H1、无横向溢出；独立设计图片压缩页检查 320/1440px。尚未覆盖 Safari、Firefox 和真实低内存手机。

本机 ZIP 对照样本是三份约 3.55MB JPG：STORE 两次用时 51–55ms，DEFLATE level 6 为 658–677ms；STORE 包约大 0.9%。两种包重新解压后内容均与输入相同。这只是该样本的打包耗时，不代表所有压缩任务均能获得同等加速。

## 检查与技术选择

- TypeScript 与生产构建通过，6 个关键工具首个 HTML 预渲染通过。
- 全量单测 79 个文件、861 个用例通过；工具路由检查及加载反馈、结果操作、运行时门禁审计通过。
- 构建仍有既有 Sass legacy API、第三方 eval 和大 chunk 提示，不能称为无警告。
- 复用已安装的 qpdf-wasm 与 gif.js，不增加依赖、不修改第三方内部源码。PDF 引擎和 GIF Worker 按需加载，不加入首页预加载。
- 没有修改 Go 后端及后台管理代码，本轮不据此前端测试声称已完成后端回归。

## 仍需完善

1. 透明 GIF 当前安全保留原文件，尚不支持真正压缩；减色后的画质也需用户结合样图选择色数和抖动。
2. 大像素 JPG/WebP 仍受浏览器 Canvas 编码和主线程限制；PNG Worker 也有像素和浏览器内存上限，需要真机专项验证。
3. qpdf 结构优化不重新降低图片质量，已经优化过的 PDF 可能几乎不变。扫描件需主动选择有损模式，实际分辨率受页数和渲染尺寸上限约束。
4. 数字签名、复杂 XFA、PDF 文件包和嵌入附件尚未完成专项验收，不应承诺改写后其全部特殊能力保持不变。
5. 本轮验证单个 PDF 的产物保留能力，不代表所有大型批次、损坏文件和所有浏览器均完成实测。
