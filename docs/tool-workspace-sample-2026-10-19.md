# 图片压缩工作区样板（2026-10-19）

基准：`9b4c11e0`，版本 `3.0.3`。本轮只迁移 `/tools/image-compress`，用于确认后续文件工具的布局方向；未升级版本、提交 Git 或部署。

## 已实现

- 为 `StandardToolPageTemplate` 增加默认关闭的 `compact` 选项：缩小标题区，隐藏装饰编号和印章，没有操作插槽时不留空页脚。其他工具默认保持原布局。
- 图片压缩改为标题与限制 → 上传 → 质量与单一压缩入口 → 文件列表 → 结果摘要与打包下载。
- 原生按钮支持 Enter、空格键打开文件选择器；处理中锁定上传、参数、移除、清空及单张下载。
- 合并重复的开始、重新压缩和下载入口。已有结果时主按钮明确为“重新压缩”；追加图片后直接打包仍会先处理未完成图片。
- 成功、失败、待处理分别计数；总节省空间只统计成功图片。失败项保留错误提示，不会误计为已节省空间。
- 使用中性表面、统一品牌主色，帮助默认收起；按工作区实际宽度适配单列，移除按钮的点击范围为 44×44px。
- 25MB、30 张和格式继续来自共享常量。压缩引擎、PNG 透明度、100% 无损编码、原图回退、唯一文件名及下载门禁保持原有实现。

## 压缩内核与保真设置（同日）

本节是当前行为，替代前文“压缩引擎保持原有实现”的阶段性说明；版本仍为 3.0.3，未提交或部署。

- PNG 默认无损，与 JPG / WebP 的质量滑块分开。减色需主动选择，并明确提示颜色和半透明细节可能变化，支持 32 / 64 / 128 / 256 色。
- PNG 直接在本地模块 Worker 中读取、解码、编码和验证，主线程不加载 UPNG，不依赖 Canvas 或 OffscreenCanvas。无损输出核对完整 RGBA，保留 ICC、色彩与分辨率信息；无法保真或体积增大时保留源文件。
- 16 位、低位灰度及交错 PNG 在无损模式下保留原文件，减色模式明确提示不支持；APNG 明确拒绝，避免丢帧。新增小图完整块与 CRC 校验，修复 UPNG 可能截断调色板输出的问题。
- JPG / WebP 默认勾选“保持原尺寸”；取消后最长边 4096px，不放大小图。原图回退交给编码器按尺寸要求判断，不再用体积判断覆盖已缩小的结果。拒绝空输出及浏览器回退到错误 MIME 的结果。
- 全批快照质量、尺寸、PNG 模式和颜色参数；处理中锁定设置。每张编码 90 秒超时，卸载时取消并回收线程或编码器。PNG 解码前限制 2400 万像素，超限、损坏、格式不支持都有明确中文错误，不回退主线程同步编码。

验证结果：

| 检查 | 结果 |

| `npm run test:unit -- --run` | 45 个文件、398 项通过，其中本工具与新压缩辅助模块 56 项 |
| `npm run check:tools`、`git diff --check` | 通过 |
| 默认模式实际 ZIP | 6 张均可独立解码；PNG RGBA、ICC、DPI 一致，16 位文件二进制一致；JPG/WebP 保持 5000×800 |
| 关闭保持原尺寸 | 实际 JPG/WebP 为 4096×655，PNG 仍为 5000×800 |
| 主动 64 色 | 实际下载为有效 PNG，63 种 RGBA 颜色，尺寸不变；像素确实改变 |
