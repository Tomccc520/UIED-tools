# UIED-Tools 3.x 前端设计规范

## 1. 设计方向

UIED-Tools 定位为“高密度、高可用、低学习成本”的专业在线工具平台。视觉上以中性灰白界面为主，品牌紫只承担主操作、链接和焦点反馈。页面应先让用户看到工具价值和主任务，热榜、推荐和运营信息属于次级内容。

不在同一操作组中使用蓝、绿、紫等多种颜色分别表示普通操作；绿色仅表示成功，红色仅表示错误或危险操作。不使用无意义的大面积渐变、过度圆角和长时间装饰动画。

## 2. 框架边界

- 主站、路由、通用布局、工具目录和大多数工具继续使用 Vue 3。
- React 仅用于已有 React 生态依赖的独立工具，通过路由级宿主按需加载。
- Vue 和 React 可以共存，但不在同一业务组件树中交叉嵌套，不共享框架内部状态。
- 双方共享 CSS 设计令牌、API 契约、登录态事件和统一结果操作规范。新页面默认使用 Vue，只有明确的 React 组件库或存量代码优势时才增加 React 岛。

## 3. 基础令牌

令牌统一定义在 `src/styles/tailwind.css`，新组件不再新增同义硬编码颜色。

| 用途 | 令牌 | 当前值 |
| --- | --- | --- |
| 品牌主色 | `--uied-color-primary` | `#5b54e8` |
| 主色悬停 | `--uied-color-primary-hover` | `#4d47d0` |
| 主色浅背景 | `--uied-color-primary-soft` | `#efefff` |
| 页面背景 | `--uied-color-page` | `#f6f7fb` |
| 内容表面 | `--uied-color-surface` | `#ffffff` |
| 主文字 | `--uied-color-text` | `#172033` |
| 次文字 | `--uied-color-text-secondary` | `#667085` |
| 边框 | `--uied-color-border` | `#e4e7ec` |
| 成功 | `--uied-color-success` | `#16845b` |
| 错误/危险 | `--uied-color-danger` | `#d92d20` |

间距使用 8px 基线：8、16、24、32px；4、12px 只用于组件内部紧密关系。圆角使用 6、8、12、16px 四档，普通卡片默认 8px，对话框或强调容器最大 16px。

## 4. 布局与响应式

- 桌面端页面水平留白 26px，移动端 12px，由公共布局提供，工具页不重复叠加。
- 工具主区域使用容器查询适配实际可用宽度，不只依赖视口媒体查询。
- 小于 640px 默认单列主任务；640–1023px 使用 2–3 列；1024px 以上根据内容宽度使用 3–5 列。
- 移动端主要点击目标不小于 44×44px。画布、表格和代码等大内容在自身容器内滚动，不撑开整页。
- 手机首屏应先展示页面标题、价值说明和主操作，推荐区每组默认最多露出 4 项。

## 5. 字体层级

| 级别 | 桌面端 | 移动端 | 用法 |
| --- | --- | --- | --- |
| 页面 H1 | 32/40px | 24/32px | 每页一个，明确工具名称 |
| 区块 H2 | 20/28px | 18/26px | 主要内容分组 |
| 子标题 H3 | 16/24px | 16/24px | 卡片或小节标题 |
| 正文 | 14–16/1.6 | 14–16/1.6 | 说明和结果 |
| 辅助文字 | 12–13/1.5 | 12–13/1.5 | 时间、状态、提示 |

标题不用 `div` 模拟；页面必须有且只有一个主 `h1`，再按内容层级使用 `h2`/`h3`。文字截断前先保证关键工具名可识别，不用单行省略遮蔽核心信息。

## 6. 组件规则

### 按钮

- 一个主任务组最多一个实心主按钮。
- 次操作使用主色浅底或描边，复制、清空等辅助操作使用中性按钮。
- 按钮必须使用 `button`，声明 `type="button"`，并有 hover、focus-visible、disabled、loading 状态。
- 只有图标的按钮必须提供 `aria-label`。

### 卡片

- 默认使用 1px 边框，阴影只在浮层或悬停反馈中出现。
- 可点击整卡必须使用链接或按钮，不用只绑定 `@click` 的 `div`。
- 悬停位移不超过 4px，不使用放大造成网格抖动。

### 表单和结果

- 输入框默认高度 40px，移动端重要输入不小于 44px。
- 标签、帮助文字、校验错误始终与输入项直接关联。
- 结果区必须处理初始、加载、空、成功和错误五种状态。动态结果使用 `role="status"` 和 `aria-live="polite"`。

## 7. 动效与可访问性

- 微交互使用 160ms，展开、面板和位移使用 240ms。禁止新增 `transition: all`。
- 所有非鼠标用户必须能通过键盘完成主任务，焦点环不得被移除。
- 装饰图标使用 `aria-hidden="true"`，图片的 `alt` 描述目的而不是文件路径。
- 支持 `prefers-reduced-motion: reduce`，打字机、光效和旋转不得阻碍内容读取。
- 项目以 WCAG 2.2 AA 作为可访问性验收目标，颜色不是唯一的状态信号。

## 8. API 与用户反馈

- 前端不直连不可控的第三方 API，统一通过同域 Go 服务、白名单上游、超时和备用源访问。
- Vue 组件只调用 `src/services` 服务层，不在页面内散落 `fetch` 和上游响应字段解析。
- 加载超过 300ms 应显示明确状态；可恢复错误提供重试；使用备用内容时告知用户，但不阻断主任务。
- 不将第三方原始错误、内部地址或堆栈直接展示给用户。

## 9. 新页面验收清单

- [ ] 文件头包含 Tomda、UIED 版权、作者和创建日期，函数有中文注释。
- [ ] 页面只有一个 H1，主任务在手机首屏可见。
- [ ] 颜色、间距、圆角、阴影和动效来自公共令牌。
- [ ] 键盘可完成全流程，所有焦点可见，图标按钮有可读名称。
- [ ] 320px、375px、768px、1440px 宽度下无水平溢出、文字重叠和主操作遮挡。
- [ ] 加载、空、成功、错误、禁用和上游降级状态均已验证。
- [ ] 新 API 先定义后台契约，再接入服务层和页面，并有单元测试。
- [ ] 通过 `build:check`、单元测试、工具目录审计与桌面/移动端浏览器回归。

## 10. 存量页面治理顺序

1. P0：修复不可用功能、前端直连第三方 API、无键盘操作和无主标题的页面。
2. P1：迁移高频硬编码颜色、`transition: all`、过度留白和过长推荐区。
3. P2：统一文字层级、图标语义、空状态和帮助文案，再处理非关键视觉细节。
4. P3：按真实使用率拆分重型依赖和大包，不为了统一技术栈重写已稳定的 Vue 或 React 工具。

## 11. 三套真实页面模板

三套模板采用“精密编辑式工具工作台”方向：用编号、细分隔线、状态标记和有限品牌色建立识别度。模板负责页面骨架、语义层级和响应式规则，业务页面继续负责数据、接口、权限和工具状态。

### 首页模板

- 骨架：`src/components/Common/PageTemplates/HomePageTemplate.vue`
- 真实展示层：`src/components/Home/HomeWorkbenchView.vue`
- 真实入口：`/`
- 固定能力：单一 H1、首屏搜索、分类快捷入口、推荐工具、学习内容和完整工具目录。
- 数据边界：首页容器继续从 Pinia 与后台公共配置读取分类、热门工具和停用状态；模板不复制业务数据。

### 标准工具页模板

- 骨架：`src/components/Common/PageTemplates/StandardToolPageTemplate.vue`
- 样板页面：`src/components/Tools/Copywriting/kfc.vue`
- 真实入口：`/tools/copywriting/kfc`
- 固定能力：工具身份区、价值说明、状态标签、主工作区、单一主操作组和辅助说明区。
- 推荐场景：文本、图片转换、计算器、格式化、随机生成等一次输入到一次结果的确定性工具。

### AI 工具页模板

- 骨架：`src/components/Common/PageTemplates/AIToolPageTemplate.vue`
- 样板页面：`src/components/Tools/AI/Analysis/PestAnalysis.vue`
- 真实入口：`/tools/ai/analysis/pest`
- 固定能力：深色 AI 身份区、上下文输入、运行状态、结果编辑、结果操作、二次 AI 动作和使用指南。
- 推荐场景：需要提示上下文、异步生成、可编辑长结果和后续追问的 AI 工具。

### 迁移规则

1. 先判断工具属于标准页还是 AI 页，不按业务分类另造页面骨架。
2. 迁移时保留原服务层、权限门禁、埋点和异常处理，只把展示结构接入具名插槽。
3. 每次优先迁移一个真实高频页面并完成桌面、移动端和接口回归，再批量推广同类页面。
4. 业务特有视觉放在页面局部样式中，不修改模板去适配单个工具；只有三个以上页面共同需要时才提升为模板能力。
5. 页面必须覆盖初始、加载、空、成功和错误状态；AI 页还需明确生成中、可编辑结果和二次动作状态。
